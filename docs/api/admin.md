# Admin API

## Registration

- `Registration(Model, options)` — Wrap an ORM model and admin options for a site
- `AdminSite(config)` — Build a comptime admin site from registered models
- `AdminSite.routes()` — Generate CRUD routes for every registered model
- `AdminSite.loadTemplates(engine)` — Load built-in admin templates into a `TemplateEngine`
- `setDb(db)` — Bind the SQLite connection used by admin handlers
- `setEngine(engine)` — Bind the template engine used by admin handlers

## Access Control

Admin handlers require a session value `role=admin`. If a request has no session user, admin redirects to `/admin/login`.

Applications are expected to provide `/admin/login`. Scaffolded apps generated by `zypher new` include that login route and authenticate against the `users` table created by:

```sh
zypher createsuperuser --db app.db
```

The command prompts for username, email, password, and password confirmation. Password input is hidden in an interactive terminal. For noninteractive use, pass all fields explicitly:

```sh
zypher createsuperuser --username admin --email admin@example.com --password Passw0rd --db app.db
```

Successful login uses the username and password, stores `username` and `role=admin` in the session, then redirects to `/admin/`.

Scaffolded apps also provide `/admin/forgot-password` and `/admin/reset-password`. The forgot-password handler accepts an email address, stores a 6-digit recovery code on the matching user row, and the reset handler accepts `email`, `code`, `password`, and `confirm_password` to replace the password hash.

## Scaffolded Admin

Every built-in CLI template registers a sample `managed_items` ORM model so `/admin/` is immediately usable. Add project-specific models by adding them to the template's `AdminSite(.{ ... })` configuration.
